# 🚀 세투연 행사 운영 플랫폼 (SISC Event Management Platform)

세투연(투자 동아리)의 다양한 행사(신입 OT, 기업분석 세미나, 스터디, 네트워킹 등)를 효율적으로 관리하고 운영하기 위해 제작된 **실서비스형 미니 플랫폼**입니다. 

기존의 파편화된 행사 운영 방식(구글 폼 신청, 수기 승인, 종이 출석부 등)을 개선하여, 신청부터 승인, 출석, 피드백 그리고 관리자 대시보드까지 하나의 웹 서비스에서 통합 관리하는 것을 목표로 합니다.

<br>

## 🎯 프로젝트 목표
1. **Spring Boot**를 활용한 실서비스형 백엔드 API 설계 및 구현
2. **React**를 연동하여 실제 사용자 흐름(User Flow)이 보이는 완성도 있는 서비스 개발
3. **AI 에이전트의 올바른 활용**: 생성된 코드를 맹목적으로 복사하지 않고, 이해·검증하며, 타인의 코드를 이어받아 개발하는 협업 능력 향상

<br>

## 🛠 기술 스택 (Tech Stack)
* **Backend:** Spring Boot, Java 17, Spring Security(JWT), Spring Data JPA
* **Database:** H2 (인메모리, PostgreSQL 호환 모드) — 로컬 시연 우선
* **Frontend:** React 18, Vite, React Router
* **기타:** RESTful API, 공통 응답 포맷(ApiResponse), 전역 예외 처리

<br>

## ⚡ 로컬 실행 및 시연 (Quick Start)

> 이 브랜치(`feature/frontend`)는 모든 백엔드 기능과 React 프론트엔드를 통합한 **데모 브랜치**입니다.
> 전체 흐름(로그인 → 행사 생성 → 신청 → 승인 → 출석 → 피드백 → 대시보드)을 바로 시연할 수 있습니다.

**사전 요구사항:** JDK 17, Node.js 18+

```bash
# 1) 백엔드 실행 (자동으로 local 프로파일이 켜져 시연용 시드 데이터가 생성됩니다)
./gradlew bootRun
# → http://localhost:8080  (H2 콘솔: http://localhost:8080/h2-console)

# 2) 프론트엔드 실행 (새 터미널)
cd frontend
npm install
npm run dev
# → http://localhost:5173  (/api 요청은 8080으로 프록시됩니다)
```

**시연 계정** (비밀번호 공통 `password123`)

| 역할 | 이메일 | 가능한 일 |
| :--- | :--- | :--- |
| ADMIN | `admin@sisc.test` | 행사 생성/수정/상태변경/삭제, 대시보드, 전체 피드백 |
| STAFF | `staff@sisc.test` | 신청자 승인/반려, 출석 코드 발급, 출석 현황 |
| MEMBER | `member@sisc.test` | 행사 신청/취소, 출석 체크, 피드백 작성 |

**테스트 실행**

```bash
./gradlew test   # 서비스/컨트롤러 통합 테스트
```

## 👥 사용자 권한 및 핵심 기능

서비스는 사용자의 권한(`MEMBER`, `STAFF`, `ADMIN`)에 따라 철저히 분리된 기능을 제공합니다.

### 1. 일반 부원 (MEMBER)
* **회원가입 및 로그인**
* **행사 조회 및 신청:** `OPEN` 상태인 행사를 확인하고 참여 신청
* **신청 상태 확인:** 내 신청이 승인되었는지 대기 중인지 확인 (`PENDING` / `APPROVED` / `REJECTED`)
* **현장 출석:** 승인된 행사에 한해, 당일 발급된 출석 코드를 입력하여 출석 체크
* **피드백 작성:** 종료된 행사에 대한 평가 및 피드백 제출

### 2. 운영진 (STAFF)
* **신청자 관리:** 행사별 신청자 목록을 확인하고, 정원 및 우선순위에 따라 승인(`APPROVE`) 또는 반려(`REJECT`)
* **출석 관리:** 행사 당일 출석 코드를 발급하고 현장 출석 현황 모니터링

### 3. 총관리자 (ADMIN)
* **행사 CRUD:** 새로운 행사 생성, 내용 및 상태 수정 (`DRAFT` ➔ `OPEN` ➔ `CLOSED` ➔ `COMPLETED` / `CANCELED`)
* **대시보드:** 전체 행사 수, 현재 모집 중인 행사, 전체 신청/승인/출석/피드백 수치 집계 및 조회
* **피드백 조회:** 부원들이 남긴 행사 피드백 전체 열람
* *(STAFF의 모든 권한 포함)*

## 🗓 개발 프로세스 및 일정 (총 8주)

본 프로젝트는 단순히 각자 기능을 나누어 만드는 것을 넘어, **전체 아키텍처 이해**와 **코드 인수인계(상속)** 에 중점을 둡니다.

| 주차 | 단계 | 주요 내용 |
| :--- | :--- | :--- |
| **1주차** | **공통 이해 만들기** | 요구사항 및 흐름 파악, ERD 및 API 명세서 초안 작성, 코딩 컨벤션 수립 (AI 적극 활용 권장) |
| **2~3주차** | **릴레이 개발 (공통)** | 팀 전체가 같은 도메인을 이해하며 개발 (회원가입/로그인, 공통 예외 처리, 행사 CRUD, Swagger) |
| **4~6주차** | **영역 분담** | 파트별 병렬 개발 (인증/공통, 행사/신청, 출석/피드백, 관리자 화면 등). 프론트는 에이전트 활용 공동 개발 |
| **7주차** | **통합 및 보강** | 프론트-백엔드 API 연결, 예외 처리 및 테스트 코드 보강, 문서화(README, Swagger) 완료 |
| **8주차** | **상속 스프린트 👑** | **내 담당이 아니었던 영역**의 코드를 물려받아 신기능 추가 또는 버그 수정 1개 이상 진행 |

## 🤖 AI 에이전트 활용 규칙
AI를 활용한 생산성 향상을 지향하지만, **코드에 대한 이해 없는 무분별한 복사-붙여넣기는 엄격히 금지**합니다.

1. **PR(Pull Request) 필수 기재 사항**
   * 사용한 프롬프트 짧게 요약
   * AI가 만든 초안 중 그대로 사용한 부분
   * 직접 검토하고 수정한 부분
2. **No-Agent Day**
   * 주 1회는 AI 에이전트 도움 없이 직접 작은 버그를 수정하거나 테스트 코드를 1개 이상 작성해야 합니다.

## 🧪 테스트 시나리오 (Test Plan)

최소 기준: **서비스 테스트 6개 이상, 컨트롤러 테스트 4개 이상**

**[필수 검증 시나리오]**
* [ ] 관리자 권한(`STAFF`, `ADMIN`)이 없는 사용자의 관리자 API 접근 차단
* [ ] 행사 상태가 `OPEN`이 아닌 경우 신청 차단
* [ ] 동일 행사에 대한 중복 신청 차단
* [ ] 신청 상태가 `PENDING`이 아닐 경우 신청 취소 차단
* [ ] 행사 신청이 승인(`APPROVED`)되지 않은 사용자의 출석 차단
* [ ] 잘못된 출석 코드 입력 시 실패 처리
* [ ] 내용이 비어있는 피드백 저장 차단
* [ ] 관리자 대시보드의 통계 수치 정상 집계 확인
